# Dependency decisions

This record covers direct third-party dependencies. Revisit it whenever a dependency is added, removed, or materially changed.

| Dependency | Capability and alternatives | Maintenance, license, and features | Footprint and safety boundary |
| --- | --- | --- | --- |
| `serde` | Typed strict JSON configuration and validated job-definition serialization; implementing general JSON parsing and validation in `std` is not reasonable. | Widely used, actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `derive` and `std` are enabled. | `serde_json` plus derive support. Safe API; no unsafe code is written by this workspace. |
| `serde_json` | Correct JSON parsing/serialization for configuration, job requests, and responses; handwritten parsers risk accepting invalid or ambiguous input. | Widely used, actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `std` is enabled. | Small focused JSON dependency; safe API. |
| `ctrlc` | Portable SIGINT/SIGTERM handling without handwritten platform FFI or unsafe code. `std` does not expose portable signal registration. | Widely used, actively maintained, MIT/Apache-2.0. Defaults disabled; only `termination` is enabled for SIGTERM support. | Pulls platform signal support (`nix`/`windows-sys` as applicable). Workspace uses its safe handler API; dependency internals are outside the workspace `unsafe_code` lint. |
| `clap` | Typed CLI parsing, validation, and generated help/version output. Manual argument parsing is possible in `std`, but duplicates mature parser behavior and makes useful help/error handling fragile. | Widely used, actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; `derive`, `error-context`, `help`, `std`, and `usage` are enabled. | Adds derive/proc-macro support and its resolved transitive dependencies. Safe parsing API; dependency internals are outside the workspace `unsafe_code` lint. |
| `axum` | Standards-compliant HTTP routing, request parsing, and JSON response construction. The standard library has no HTTP server; a custom parser would be fragile. | Widely used, actively maintained, MIT/Apache-2.0. Defaults disabled; only `http1`, `json`, `query`, and `tokio` are enabled. | Brings Hyper, Tower core, and JSON response support. Safe router/serve APIs; dependency internals are outside the workspace `unsafe_code` lint. |
| `reqwest` | Worker-initiated HTTPS polling and report delivery with client certificates, request deadlines, and redirect rejection. A handwritten HTTP/TLS client would be unsafe and fragile. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `rustls` is enabled. The `rustls` feature selects reqwest's supported AWS-LC provider and platform certificate verifier for server trust. | Adds Hyper/Rustls and AWS-LC; response and request bodies are capped at 128 KiB. JSON is encoded with the workspace's strict serializer, so reqwest's optional JSON feature is unnecessary. The safe client identity API holds the worker certificate and private key in memory; callers must load credentials from protected configuration/storage. TLS implementation internals are outside the workspace unsafe lint. |
| `tower` | `ServiceExt::oneshot` drives the Axum router in tests to verify authentication middleware, body limits, and route responses without binding a socket. Direct handler tests would miss these HTTP layers. | Actively maintained, MIT licensed. Defaults disabled; only the test utility feature `util` is enabled. | Already present transitively through Axum; the direct dev dependency adds no production feature or runtime footprint. Safe service test API. |
| `tokio` | Async runtime, TCP listener integration, timers, cooperative task selection, watch signals, bounded semaphores, and a bounded blocking executor for SQLite/filesystem work. No equivalent async runtime exists in `std`. | Widely used, actively maintained, MIT license. Defaults disabled; only `macros`, `net`, `rt`, `rt-multi-thread`, `sync`, and `time` are enabled directly. Axum's `tokio` feature also uses its required Tokio features. | Brings the runtime, platform I/O, and bounded admission primitive. Safe runtime/listener APIs; dependency internals are outside the workspace `unsafe_code` lint. |
| `rusqlite` | Transactional SQLite storage for manager-owned jobs and run intent, plus separately worker-owned accepted runs and observations; implementing a correct storage engine in `std` is not reasonable. | Actively maintained Rust SQLite binding, MIT licensed; SQLite itself is public domain. Defaults disabled; only `bundled` is enabled to pin the SQLite implementation used by the daemon and avoid a system SQLite build/runtime prerequisite. | Bundles SQLite C sources and `libsqlite3-sys`; manager and worker each open only their own database and use safe connection/statement/transaction APIs. Third-party C/Rust internals are outside the workspace unsafe lint. The system SQLite alternative was rejected to keep Linux builds reproducible across hosts. |
| `nix` | Safe Unix process-group signaling is required to clean up ordinary descendants after their leader exits and on daemon shutdown; `std::process::Child::kill` targets only the direct child. Polling is used to make output-reader cancellation responsive during startup cleanup. | Actively maintained, MIT licensed; defaults disabled and only `poll`, `process`, and `signal` are enabled for readiness polling, process identifiers, and group signaling. | Small Unix API surface over libc. The worker and process crates use safe wrappers; dependency internals are outside the workspace unsafe lint. Platform process groups are not a sandbox and descendants may escape them. |
| `base64` | The log API must transport arbitrary binary bytes in JSON without changing byte offsets or requiring valid UTF-8, and the manager uses opaque URL-safe encodings for validated pagination cursors. The standard library has no Base64 encoder. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `alloc` is enabled for bounded JSON log encoding. | Small focused encoding dependency. Log encoding and cursor payloads are bounded; dependency internals are outside the workspace unsafe lint. |
| `landlock` | Linux filesystem restrictions need kernel Landlock rules keyed to open path descriptors. Handwritten syscall bindings are error-prone and violate the workspace unsafe-code policy. | Official `landlock-lsm/rust-landlock` v0.4.7, actively maintained, MIT/Apache-2.0. Defaults disabled; the crate declares no optional features. | Adds `enumflags2`, `libc`, and `thiserror`. The process crate uses safe `PathFd`, `Ruleset`, and hard compatibility APIs; dependency internals may use unsafe code, while workspace unsafe remains forbidden. ABI v3 is required so truncate and cross-directory rename rules are enforced. |
| `close_fds` | Mark inherited descriptors close-on-exec before the daemon starts worker threads, preventing ambient file handles from bypassing a later Landlock policy. `std::process::Command` only closes descriptors already marked close-on-exec. | `close_fds` v0.3.2, MIT licensed. Defaults disabled; no optional features are needed. | Adds `cfg-if` and uses `libc` for platform support. A safe thread-aware descriptor scan flags existing descriptors; it preserves daemon access while ensuring child execs do not inherit them. |

All dependencies are centralized in `[workspace.dependencies]`. Review the resolved transitive graph in `Cargo.lock` as part of changes.

The cgroup v2 adapter intentionally uses `std::fs` against the documented cgroupfs control files rather than a cgroup-management dependency. It supports only the selected CPU, memory, swap, PID, process-placement, kill, and populated-state interfaces; it does not configure systemd or ancestor controllers. This keeps the API surface narrow and avoids adding a library whose broader host-integration behaviors are out of scope. All workspace code uses safe Rust; `cgroup.procs` placement is performed by a fresh internal launcher before it calls the safe Unix `CommandExt::exec` method.
