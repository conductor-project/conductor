# Dependency decisions

This record covers direct third-party dependencies. Revisit it whenever a dependency is added, removed, or materially changed.

| Dependency | Capability and alternatives | Maintenance, license, and features | Footprint and safety boundary |
| --- | --- | --- | --- |
| `serde` | Typed strict JSON configuration and validated job-definition serialization; implementing general JSON parsing and validation in `std` is not reasonable. | Widely used, actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `derive` and `std` are enabled. | `serde_json` plus derive support. Safe API; no unsafe code is written by this workspace. |
| `serde_json` | Correct JSON parsing/serialization for configuration, job requests, and responses; handwritten parsers risk accepting invalid or ambiguous input. | Widely used, actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `std` is enabled. | Small focused JSON dependency; safe API. |
| `ctrlc` | Portable SIGINT/SIGTERM handling without handwritten platform FFI or unsafe code. `std` does not expose portable signal registration. | Widely used, actively maintained, MIT/Apache-2.0. Defaults disabled; only `termination` is enabled for SIGTERM support. | Pulls platform signal support (`nix`/`windows-sys` as applicable). Workspace uses its safe handler API; dependency internals are outside the workspace `unsafe_code` lint. |
| `clap` | Typed CLI parsing, validation, and generated help/version output. Manual argument parsing is possible in `std`, but duplicates mature parser behavior and makes useful help/error handling fragile. | Widely used, actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; `derive`, `error-context`, `help`, `std`, and `usage` are enabled. | Adds derive/proc-macro support and its resolved transitive dependencies. Safe parsing API; dependency internals are outside the workspace `unsafe_code` lint. |
| `clap_complete` | Generates shell completion scripts from the implemented Clap command tree; handwritten Bash/Zsh/Fish/PowerShell completion logic would duplicate parsing rules and drift from help. | Maintained by the Clap project, dual licensed MIT/Apache-2.0. Defaults disabled; no optional features are enabled. | Adds the small completion generators and uses the existing Clap command model. Generation writes only to stdout; dependency internals are outside the workspace `unsafe_code` lint. |
| `axum` | Standards-compliant HTTP routing, request parsing, and JSON response construction. The standard library has no HTTP server; a custom parser would be fragile. | Widely used, actively maintained, MIT/Apache-2.0. Defaults disabled; only `http1`, `json`, `query`, and `tokio` are enabled. | Brings Hyper, Tower core, and JSON response support. Safe router/serve APIs; dependency internals are outside the workspace `unsafe_code` lint. |
| `reqwest` | Worker-initiated HTTPS polling, enrollment, and report delivery with client certificates, request deadlines, redirect rejection, and exclusive use of the operator-provisioned manager CA. Also sends bounded local HTTP readiness probes and provides the typed operator API client; a handwritten HTTP/TLS client would be unsafe and fragile. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; the workspace enables `rustls`, `json`, and `stream`; the conductor-api client additionally uses streaming response consumption. The `rustls` feature selects reqwest's supported AWS-LC provider and platform certificate verifier for server trust. | Adds Hyper/Rustls and AWS-LC; manager response/request bodies are capped at 128 KiB and readiness bodies are not consumed (declared lengths above 8 KiB are rejected). The API client enforces a configurable finite limit while consuming actual success and error response bytes, and uses the API crate's configured CA certificate for TLS trust. JSON is encoded with the workspace serializer. `tls_certs_only` disables platform roots for the configured manager connection. The safe client identity API holds the worker certificate and private key in memory; callers must load credentials from protected configuration/storage. TLS implementation internals are outside the workspace unsafe lint. |
| `axum-server` | TLS serving for the Axum worker transport using a configured Rustls `ServerConfig`; the existing Axum listener only serves plain HTTP. | Maintained Axum-compatible server, MIT licensed. Defaults disabled; only `tls-rustls` is enabled. | Adds the safe Rustls acceptor and server control APIs; this feature uses the same AWS-LC provider as the existing reqwest TLS client. |
| `axum-server-mtls` | Adds verified client certificate chains to Axum request extensions, which the worker authenticator resolves to durable certificate fingerprints. Avoids custom TLS acceptor code. | Published MIT-licensed adapter for `axum-server` and Rustls. Defaults disabled; no optional features are needed. | Adds X.509 parsing support. The adapter only exposes peer certificates; Rustls verifies chains and the manager database enforces active identity and revocation. |
| `rcgen` | Generates CA and server keys, validates signed CSRs, and issues worker certificates. Handwritten X.509 construction and signing are unsafe. | Maintained under the Rustls organization, dual licensed MIT/Apache-2.0. Defaults disabled; only `aws_lc_rs`, `pem`, `x509-parser`, and `zeroize` are enabled. | Adds certificate generation, PEM, CSR/X.509 parsing, time support, and key zeroization. Worker private keys are generated locally and only the CSR crosses the network. |
| `rustls` | Builds HTTPS server configuration with verified client certificate chains and a pinned manager CA trust root. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `aws_lc_rs`, `std`, and `tls12` are enabled. | Uses the AWS-LC provider shared with reqwest. Rustls server APIs verify presented client chains; the identity repository additionally checks expiry, active certificate, and revocation. |
| `getrandom` | Supplies operating-system randomness for 256-bit one-time enrollment credentials. Predictable credentials are not acceptable. | Actively maintained, dual licensed MIT/Apache-2.0 or Apache-2.0 depending on platform. Defaults disabled; only `std` is enabled. | Small OS entropy interface. The returned token is shown once and only its SHA-256 digest is persisted. |
| `sha2` | Hashes enrollment credentials before persistence, fingerprints presented certificates for durable identity lookup, and verifies operator-provisioned executable SHA-256 digests before worker launch. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; no optional features are enabled. | Small digest implementation; token entropy is 256 bits and the token itself is never stored. Executable hashing uses a fixed-size stack buffer. |
| `subtle` | Compares operator bearer-token digests in constant time; ordinary byte equality can reveal matching prefixes through timing. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; no optional features are enabled. | Small constant-time comparison primitive with no additional runtime dependency. The workspace still uses only safe Rust; dependency internals are outside the workspace unsafe lint. |
| `time` | Sets and persists X.509 validity windows with the same UTC epoch used by manager expiry checks. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `std` is enabled. | Adds bounded date/time conversion. The daemon rejects certificates based on database expiry as well as Rustls handshake validation. |
| `zeroize` | Clears serialized private-key strings when the CA/key-material objects are dropped; rcgen's zeroize feature clears internal key material where supported. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `alloc` is enabled. | Small safe memory-clearing API. It does not protect keys from privileged process inspection or replace filesystem access controls. |
| `x509-parser` | Confirms that the manager's persisted CA certificate public key matches its protected private key before the CA is used. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; no optional features are enabled. | Parsing only; signature verification is performed by Rustls. Also used by rcgen's CSR validation feature. |
| `tower` | `ServiceExt::oneshot` drives the Axum router in tests to verify authentication middleware, body limits, and route responses without binding a socket. Direct handler tests would miss these HTTP layers. | Actively maintained, MIT licensed. Defaults disabled; only the test utility feature `util` is enabled. | Already present transitively through Axum; the direct dev dependency adds no production feature or runtime footprint. Safe service test API. |
| `tokio` | Async runtime, TCP listener integration, timers, cooperative task selection, watch signals, bounded semaphores, and a bounded blocking executor for SQLite/filesystem work. No equivalent async runtime exists in `std`. | Widely used, actively maintained, MIT license. Defaults disabled; only `macros`, `net`, `rt`, `rt-multi-thread`, `sync`, and `time` are enabled directly. Axum's `tokio` feature also uses its required Tokio features. | Brings the runtime, platform I/O, and bounded admission primitive. Safe runtime/listener APIs; dependency internals are outside the workspace `unsafe_code` lint. |
| `rusqlite` | Transactional SQLite storage for manager-owned jobs and run intent, plus separately worker-owned accepted runs and observations; implementing a correct storage engine in `std` is not reasonable. | Actively maintained Rust SQLite binding, MIT licensed; SQLite itself is public domain. Defaults disabled; `bundled` pins the SQLite implementation and `backup` enables the supported online backup API. | Bundles SQLite C sources and `libsqlite3-sys`; manager and worker each open only their own database and use safe connection/statement/transaction/backup APIs. Third-party C/Rust internals are outside the workspace unsafe lint. The system SQLite alternative was rejected to keep Linux builds reproducible across hosts. |
| `nix` | Safe Unix process-group signaling is required to clean up ordinary descendants after their leader exits and on daemon shutdown; `std::process::Child::kill` targets only the direct child. Polling is used to make output-reader cancellation responsive during startup cleanup. `O_NOFOLLOW` protects operator-token file loading from symlink substitution. | Actively maintained, MIT licensed; defaults disabled and only `fs`, `poll`, `process`, and `signal` are enabled for no-follow file opening, readiness polling, process identifiers, and group signaling. | Small Unix API surface over libc. The worker, process, and CLI crates use safe wrappers; dependency internals are outside the workspace unsafe lint. Platform process groups are not a sandbox and descendants may escape them. |
| `base64` | The log API must transport arbitrary binary bytes in JSON without changing byte offsets or requiring valid UTF-8, and the manager uses opaque URL-safe encodings for validated pagination cursors. The standard library has no Base64 encoder. | Actively maintained, dual licensed MIT/Apache-2.0. Defaults disabled; only `alloc` is enabled for bounded JSON log encoding. | Small focused encoding dependency. Log encoding and cursor payloads are bounded; dependency internals are outside the workspace unsafe lint. |
| `landlock` | Linux filesystem restrictions need kernel Landlock rules keyed to open path descriptors. Handwritten syscall bindings are error-prone and violate the workspace unsafe-code policy. | Official `landlock-lsm/rust-landlock` v0.4.7, actively maintained, MIT/Apache-2.0. Defaults disabled; the crate declares no optional features. | Adds `enumflags2`, `libc`, and `thiserror`. The process crate uses safe `PathFd`, `Ruleset`, and hard compatibility APIs; dependency internals may use unsafe code, while workspace unsafe remains forbidden. ABI v3 is required so truncate and cross-directory rename rules are enforced. |
| `close_fds` | Mark inherited descriptors close-on-exec before the daemon starts worker threads, preventing ambient file handles from reaching workload processes or bypassing a later Landlock policy. `std::process::Command` only closes descriptors already marked close-on-exec. | `close_fds` v0.3.2, MIT licensed. Defaults disabled; no optional features are needed. Its upstream support lists Linux and macOS as tested CI targets. | Adds `cfg-if` and uses `libc` for OS descriptor enumeration and flag changes. A safe thread-aware descriptor scan flags existing descriptors; it preserves daemon access while ensuring child execs do not inherit them. It is a direct dependency only on Linux and macOS targets. |
| `sysinfo` | Reads logical CPU count and total RAM through supported Linux and macOS system APIs without parsing `/proc` or invoking platform-specific command-line tools. `std::thread::available_parallelism` bounds allocatable CPU to what the daemon can use. Defaults disabled; only `system` is enabled. The `multithread`, process, disk, network, component, serde, and user features remain disabled. | Adds the focused system-information backend and platform-specific transitive support. The workspace calls only safe CPU and memory APIs and does not enumerate processes. Dependency internals are outside the workspace `unsafe_code` lint. |

| `async-trait` | Implements Hickory's async request-handler interface without hand-written boxed futures. | Actively maintained, dual licensed MIT/Apache-2.0. | `ipnet` | Parses and matches CIDR ranges used to restrict DNS clients and validate nonoverlapping private IPv4 overlay pools. | `iroh` | Rust-native authenticated QUIC transport and endpoint identity for the worker overlay. | `iroh-base` | Parses Iroh endpoint identities at the authenticated worker enrollment boundary; a local hex-only check would accept malformed public keys. | Iroh 1.3.0, maintained by n0, dual licensed MIT/Apache-2.0, Rust 1.91 minimum. | `bytes` | Owns bounded IPv4 packet payloads passed to Iroh QUIC datagrams without a custom packet buffer. | `bytes` 1.12.1, dual licensed MIT/Apache-2.0. Pinned exactly; defaults disabled. | Small byte-buffer type used only at the overlay transport boundary. Workspace code uses safe constructors and slices; no unsafe code is added. |
| `tun-rs` | Creates and asynchronously reads/writes a TUN interface for the worker's IPv4 packet adapter. The standard library has no TUN API; handwritten platform device handling would be fragile. | `tun-rs` 2.8.13 from the maintained [upstream project](https://github.com/tun-rs/tun-rs), Apache-2.0, Rust 1.75 minimum. Implemented dependencies are centralized in `[workspace.dependencies]`. The
Iroh, Iroh Base, bytes, tun-rs, rtnetlink, and futures-util rows record the
selected MVP5 dependency decisions before their implementation branches are
integrated; those branches add the workspace pins and `Cargo.lock` entries.
Review the resolved transitive graph in `Cargo.lock` when integrating each
dependency.

The cgroup v2 adapter intentionally uses `std::fs` against the documented cgroupfs control files rather than a cgroup-management dependency. It supports only the selected CPU, memory, swap, PID, process-placement, kill, and populated-state interfaces; it does not configure systemd or ancestor controllers. This keeps the API surface narrow and avoids adding a library whose broader host-integration behaviors are out of scope. All workspace code uses safe Rust; `cgroup.procs` placement is performed by a fresh internal launcher before it calls the safe Unix `CommandExt::exec` method.
